## Что это

Эксперимент: что если поиск исполнителей и заказов сделать не каталогом с фильтрами, а лентой карточек. Клиент листает специалистов, исполнитель — заказы. Понравилось — в избранное или сразу написать.

Внутри — бот на mock-данных: 6 специалистов и 6 заказов. Никакой базы, авторизации и реальных контактов. Цель была проверить механику и тексты, а не запустить биржу.

---

## Что умеет

- Выбор роли: «Я клиент» / «Я исполнитель».
- Фильтр по профессии для клиента и по категории — для исполнителя.
- Карточка специалиста: имя, профессия, опыт, ставка, город, теги, портфолио, описание.
- Карточка заказа: заголовок, описание, бюджет, навыки.
- Действия: «Написать / Откликнуться», «Пропустить», «В избранное».
- Избранные специалисты и заказы.
- Переход к следующей карточке после действия.
- Экран «карточки закончились» с возвратом к поиску.

## Сценарий

```mermaid
flowchart TD
    A[/start] --> B[Выбор роли]
    B -->|Я клиент| C[Профессия]
    C --> D[Карточка специалиста]
    D -->|Написать| E[Контакт]
    D -->|Пропустить| D2[Следующая карточка]
    D -->|В избранное| F[Избранное]
    B -->|Я исполнитель| G[Категория заказа]
    G --> H[Карточка заказа]
    H -->|Откликнуться| I[Отклик]
    H -->|Пропустить| H2[Следующий заказ]
    H -->|В избранное| J[Избранное]
```

## Запуск

Нужен [Bun](https://bun.com) и токен от [@BotFather](https://t.me/BotFather).

```bash
bun install
cp .env.example .env
```

В `.env`:

```env
BOT_TOKEN=123456:AA...
```

```bash
bun run start
```

## Как это работает

- Состояние на чат: текущий контекст (`swiping_specs` / `swiping_orders`), перемешанный список, индекс, избранное, отклики.
- Списки перемешиваются при входе, чтобы каждый раз порядок был разным.
- Карточка редактируется в том же сообщении — лента не засоряет чат.
- «Написать» и «Откликнуться» показывают контакт/подтверждение и остаются на карточке.
- Избранное хранится в памяти и сбрасывается при перезапуске.
- `callback_data` разбирается на действие и аргументы, поэтому один обработчик покрывает фильтры, карточки и избранное.

## Ограничения

- Только mock-данные, без БД и реальных пользователей.
- Нет регистрации, профилей и модерации.
- Нет реальных сообщений между клиентом и исполнителем: бот показывает контакт, но не создаёт чат.
- Нет верификации, рейтингов и отзывов.
- Нет оплаты и монетизации.
